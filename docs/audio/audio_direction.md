## 1. 방향과 무드 원칙

**한 줄**: 회색 세계는 조용하고 비어 있다. 색(감정)이 돌아올 때마다 악기가 하나씩 돌아오고, 남매의 두 선율은 함께일 때만 끝맺는다.

| # | 원칙 | 들리는 방식 |
|---|---|---|
| 1 | **여백이 재료다** | 회색 장면은 음이 적다. 단음 피아노, 바람, 멀리서 나는 생활 소음. 침묵을 두려워하지 않는다 |
| 2 | **색 = 음색** | 감정 색마다 악기가 정해져 있다(§4). 그 색을 되찾으면 그 악기가 음악에 들어온다 |
| 3 | **적은 모티프, 많은 변주** | 새 선율을 계속 만들지 않는다. 하늘·별 모티프 두 개를 장소와 감정에 맞게 바꿔 쓴다 |
| 4 | **슬픔에서 따뜻함으로** | 단조와 장조 사이를 오가되(나단조 ↔ 라장조), 결말은 장조로 해결한다(필러 3 "상실 후의 따뜻함") |
| 5 | **부드러운 음색** | 날카로운 고음, 거친 디스토션을 피한다. 펠트 피아노, 오르골, 목관, 약한 테이프 질감 |
| 6 | **칩튠이 아니다** | 픽셀아트지만 음악은 어쿠스틱 계열이다. 짧은 UI 소리만 칩 느낌(jsfxr)을 허용한다 |
| 7 | **소리만으로 전하는 정보는 없다** | 잔향의 거리 소리 같은 단서는 반드시 화면 정보와 함께 준다(접근성). 반대로 화면 정보에 소리도 곁들인다 |

## 2. 레퍼런스 — 원리만 가져온다

계획서 ②-5의 장르 레퍼런스에서 **구조 원리만** 참고한다.

| 참고하는 원리 | 어디서 본 원리인가 | 이 게임에서 |
|---|---|---|
| 회복할수록 표현 수단이 늘어난다 | GRIS(색 회복 = 능력 해금) | 색 회복 = 악기 회복(§4, §5) |
| 한두 개의 주제 선율을 끝까지 변주해 큰 감정을 만든다 | To the Moon(적은 시스템으로 큰 감정) | 남매 모티프 두 개만으로 전 곡을 엮는다(§3) |
| 이별 장면을 크게 울리지 않고 담담하게 둔다 | Spiritfarer(이별 엔딩의 톤) | 희생 엔딩은 악기를 빼 나가는 방식(§3-6) |

**금지 규칙**

1. 기존 게임·영화 음악의 선율, 화성 진행의 특징적인 부분, 편곡 구조를 인용하지 않는다.
2. 레퍼런스 곡을 옆에 틀어 두고 따라 쓰지 않는다. 원리를 글로 적은 뒤 레퍼런스를 끄고 쓴다.
3. AI 생성 도구 프롬프트에 기존 게임·작곡가·곡 이름을 넣지 않는다("○○ 풍으로" 금지, §10).

## 3. 남매 라이트모티프

### 3-1. 공통 틀

| 항목 | 값 |
|---|---|
| 조성 | 라장조(D major). 슬픈 변주는 나단조(B minor) |
| 박자·빠르기 | 3/4박, **72 BPM**(한 마디 2.5초) |
| 길이 | 각 **4마디**(10초) |
| 화성 | 마디마다 D – Bm – G – A (I – vi – IV – V) |
| 핵심 장치 | 두 모티프 모두 **4마디째 V(A)에서 끝나 해결되지 않는다.** 둘이 겹칠 때만 **5마디째(I, D)**가 생겨 해결된다 |

> 서사와 같은 구조다. 따로 있을 때는 끝맺지 못하고, 함께일 때만 끝맺는다. 진실 공개 전에는 5마디째를 절대 들려주지 않는다(§3-5, "음악의 R-NAME").

### 3-2. 하늘 모티프 「물결」

| 항목 | 내용 |
|---|---|
| 감정·색 | 그리움, 파랑, 물결 기호 |
| 음역·악기 | 중음역(D4~A4), 펠트 피아노 |
| 윤곽 | 내려갔다 살짝 올라오는 **물결 모양 하행** |
| 음도 스케치 | 마디1 `5 – 3 – 4` / 마디2 `3 – 1 – 2` / 마디3 `1 – 6̣ – 7̣` / 마디4 `2`(길게, 해결 안 됨) |
| 리듬 | 긴 음 – 짧은 음 – 보통 음. 숨 쉬듯 느리게 |

### 3-3. 별 모티프 「해」

| 항목 | 내용 |
|---|---|
| 감정·색 | 온기, 노랑, 해 기호 |
| 음역·악기 | 고음역(D5~B5), 오르골·글로켄슈필 |
| 윤곽 | 5음계로 **뛰어오르는 상행** |
| 음도 스케치 | 마디1 `1 – 2 – 3` / 마디2 `6 – 5 – 3` / 마디3 `1' – 6 – 5` / 마디4 `5`(길게, 열린 채로) |
| 리듬 | 짧은 음이 반짝이듯. 하늘 모티프보다 음이 많다 |

음도 스케치는 방향을 정하기 위한 **[제안]**이다. 작곡 단계에서 자유롭게 바꾸되 §3-1의 핵심 장치(4마디째 미해결, 함께일 때만 5마디째 해결)는 지킨다.

### 3-4. 결합 규칙

1. 두 모티프는 같은 화성 위에서 **동시에 연주해도** 성립하게 쓴다. 강박에서 각자 화음 구성음을 쓰고, 두 선율이 같은 방향으로 8도·5도를 이어 가지 않게 한다.
2. 음역을 나눈다: 하늘은 중음역, 별은 고음역. 겹쳐도 서로 가리지 않는다.
3. 결합형("남매 테마")은 4마디 동시 연주 + **5마디째 해결**: 하늘 `2 → 1`, 별 `5 → 1'`.
4. 확장형(엔딩·크레딧): 결합형 2회 + 현악 대선율.

### 3-5. 쓰는 시기 — 음악의 R-NAME

진실 공개(`ev_ch4_storm`) 전에는 두 모티프를 **완전히 겹쳐 연주하지 않는다.** 이름이 화면에 나오지 않듯, 둘의 관계도 음악에서 완성되지 않는다.

| 시기 | 하늘 모티프 | 별 모티프 | 겹침 |
|---|---|---|---|
| 프롤로그 ~ 챕터 1 교대 파트 | 하늘 파트에서 원형 | 별 파트에서 원형 | 없음 |
| 챕터 1 광장(`ch1_square`) | 번갈아 등장 | 번갈아 등장 | **1마디**("같은 말 동시에" 순간) |
| 챕터 2 | 카페·다락방 변주 | 놀이공원 변주 | 다락방에서 1마디 |
| 챕터 3 협력 작품(`ch3_artwork`) | 함께 시작 | 함께 시작 | **2마디** 겹치고 끊긴다(가장 가까이 감) |
| 챕터 4 감정 충돌 | 나단조, 엇박 | 나단조, 엇박 | 서로 부딪힌다 |
| 챕터 4 폭풍 | 파편 | 파편 | 소음 속 조각 |
| 챕터 4 폭풍 후(`ch4_storm_after`) | — | — | **처음으로 4마디 완전 겹침 + 5마디째 해결** |
| 챕터 5 | 결합형이 기본 | | |

### 3-6. 엔딩 편곡

| 엔딩 | 편곡 |
|---|---|
| 보호 | 하늘 모티프가 이끌고 별 모티프는 멀리 대선율. 5마디째 해결은 하되 피아노 혼자 |
| 치유 | 별 모티프가 이끌고 하늘 모티프는 대선율. 오르골 혼자 해결 |
| 가족 | 결합형 확장 + 현악. 5색 악기가 모두 들어온다 |
| 기적 | 가족 편곡 + **빨강(무지개) 음색**인 현악 합주가 처음 들어온다 |
| 희생 | 바친 사람의 모티프 악기가 한 마디씩 빠져나가고, 남은 사람이 혼자 연주한다. 마지막 5마디째에서 빠졌던 악기가 **해결음 한 음**만 낸다 |

## 5. 적응형 음악

| 장치 | 규칙 | 우선순위 |
|---|---|---|
| **채도 연동 저역 통과** | Music·Ambience 버스에 저역 통과 필터. 차단 주파수 = 3,000 Hz × (20,000 / 3,000)^`global_saturation` (지수 보간). 채도 0.0 → 3 kHz(먹먹함), 0.5 → 약 7.7 kHz, 1.0 → 20 kHz(열림). 전역 채도 값은 [progression.md](../gdd/progression.md) §4 | MVP |
| 감지 중 | 음악 −3 dB, 감지 지속음이 앞으로 | MVP |
| 공명 퍼즐 | 장면 BGM을 그대로 두고 −6 dB + 추가 저역 통과 2 kHz + `amb_resonance` 패드. 완성하면 그 잔향 감정 악기의 짧은 스팅어. **퍼즐 전용 BGM은 만들지 않는다** | MVP |
| 대사 덕킹 | 대사창이 열리면 음악 −4 dB(0.3초) | MVP |

| 마디 맞춤 전환 | 마디 경계에서 곡 전환 | P2 |

### 8-1. 루프 만들기 규칙

1. 루프 본체는 **마디 단위**로 정확히 자른다(72 BPM, 3/4박 → 한 마디 2.5초).
2. 루프 끝의 잔향(리버브 꼬리)은 잘라 루프 시작 부분에 겹쳐 넣는다(꼬리 접기). 이음매에서 소리가 뚝 끊기지 않게 한다.
3. 자르는 지점은 파형 0점에 맞춘다(딸깍 소리 방지).
4. 인트로가 있으면 `loop_offset`에 인트로 길이(초)를 적고, 값을 매니페스트(계약 변경 제안 A4)에 기록한다.
5. OGG 임포트의 `bpm`, `beat_count`, `bar_beats`도 채운다(마디 맞춤 전환용). 옵션 이름은 Godot 4.7 문서로 확인 **TODO-확인**.
6. 반드시 게임 안에서 3회 이상 반복해 들어 보고 확정한다.

| 확인 | Godot | 임포트 설정(루프), 게임 안에서 반복 재생, 버스 볼륨 조정 |

**모티프 시안 3안 (WP-11 완료 기준: "30초 모티프 3안 중 1개 선정")**

각 시안은 하늘 4마디 → 별 4마디 → 겹침 4마디 + 해결 1마디 = 13마디(약 32초)다. 단 이 데모는 "진실 공개 후" 구조를 미리 들어 보는 용도이고, 게임 안에서는 §3-5 규칙을 따른다.

| 안 | 하늘 / 별 악기 | 성격 | 걱정되는 점 |
|---|---|---|---|
| A (기본안) | 펠트 피아노 / 오르골 | 가장 따뜻하다 | 흔한 조합 → 모티프 윤곽으로 개성을 낸다 |
| B | 나일론 기타 / 플루트 | 야외·여행 느낌 | 회색 세계의 정적과 덜 맞을 수 있다 |
| C | 테이프 질감 신스 리드 / 벨 | 픽셀아트와 결이 맞고 독특하다 | 감정 표현의 폭이 좁다 |

고르는 기준(개발자가 직접 판정): ① 흑백 화면 영상 위에서 따뜻하게 들리는가 ② 두 모티프를 따로 들어도 각자 알아볼 수 있는가 ③ 겹쳤을 때 5마디째 해결이 확실히 느껴지는가 ④ LMMS로 혼자 다시 만들 수 있는가 ⑤ 3분 반복해도 피곤하지 않은가.

## 10. AI 오디오 정책과 외부 소스

### 10-1. AI 오디오

1. AI 음악·효과음 생성 도구는 **스케치와 레퍼런스 용도로만** 쓴다: 무드 확인, 빠르기·편성 실험, 개발 중 임시 소리.
2. AI가 만든 오디오를(일부라도) **출시 빌드에 넣으려면** 반드시 [docs/ai_usage.md](../ai_usage.md)에 한 줄을 추가로 기록한다(날짜, 경로, 도구, 용도, 출시물 포함, 사람이 수정했는지, 공개 대상). **기록이 없으면 출시물에 넣지 않는다**(AGENTS.md §3-9). 스팀 Content Survey의 AI 공개 대상이다.
3. 넣기 전에 그 서비스의 상업 이용 약관을 확인한다.
4. 프롬프트에 기존 게임·작곡가·곡 이름을 넣지 않는다. 실존 인물의 목소리를 흉내 내지 않는다.
5. 임시 AI 소리는 파일 이름을 `tmp_ai_`로 시작한다. 출시 전에 이 접두사가 남아 있으면 빌드를 막는다(계약 변경 제안 A5).

### 10-2. 외부 소리 소스

| 라이선스 | 사용 |
|---|---|
| CC0 | 쓸 수 있다(권장) |
| CC-BY | 쓸 수 있다. 크레딧에 반드시 표기 |
| 비상업(NC)·변경금지(ND) | **쓰지 않는다**(유료 출시 계획이 있으므로) |

출처는 `docs/audio/sources.md`(WP-22에서 만든다)에 파일별로 기록한다.
